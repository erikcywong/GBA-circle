一、概念：什么是「商号唯一锚点」

锚点（Anchor）不是优惠券，不是活动码。它是一套「商号身份 + 永久归因 + 合规结算」的三位一体机制。 把三个词拆开看，每一句都针对原方案的漏洞。

1商号身份

一个法人 / 社团 / 持牌实体对应唯一一个锚点码（MA-行业-序号）。不允许一个商号开多个码刷量，也不允许一个码挂多个商号。

锚点码绑定：商号名称、BR 号 / 社团注册号 / 保险中介牌照号、行业类别、结算通道、合规通道类型、联系人。

2永久归因

客户首次扫该锚点码，档案即被打上 source_merchant 标签。之后哪怕他自己开车再来、哪怕隔了半年，消费仍归集到该锚点。

为防止「薅一次吃一辈子」，归因设窗口 + 分层：首单全酬、窗口内复购半酬、窗口外转会员股息。详见第七节。

3合规结算

三类主体受的法律约束完全不同。现金佣金不能一刀切——车主会（非牟利）、保险（受监管）收现金佣金会触雷。

所以结算分四条通道：会员福利采购 / 服务费 / 单向会员折扣+联合活动费 / 会籍互认。详见第四节。

◆ 一句话定位

商号锚点是入口层，OnePass（一码通行）是身份层。客户先扫商号锚点码领「车主礼包」并绑定车牌， 之后就平滑切进 OnePass 的三步通行链路。它不替代一码通行，它从前面喂流量给一码通行。

二、为什么是车主会、代办机构、保险公司

这三类主体共同握着「港车北上自驾客」在决策链上最靠前、最刚需、最高信任的三个触点。 园区在他们面前不是「又一个广告位」，而是「他们会员 / 客户本来就要去的目的地」。

唯一性规则（防止刷量的 5 条铁律）

  • 一法人一码：商号主体唯一，子门店 / 子群用「同锚点 + 子媒介参数」区分，不另开码。
  • 一码多媒介：同一锚点的海报 / WhatsApp / EDM / 名片 / 店内立牌，统一用 ?m=MA-CLUB001&s=poster|ws|edm|card 的子参数区分投放效果，而不是新增码。这是「唯一锚点」的技术核心。
  • 一商号一账本：该商号全部客户、消费、复购、权益池，归集到单一 merchant ledger，后台只看自己那一页。

  • 一风控闸门：同设备 / 同 IP 限频、必须绑车牌或实名、扫码到到园时间窗 ≥2 小时，三道闸防刷单。

四、三类主体的合规通道差异（本页最硬的部分）

这是锚点计划能不能落地的分水岭。原方案「统一 15–25% 现金佣金」在旅行社身上合规， 在车主会与保险公司身上直接触雷。下面把每条红线写死。

主体监管约束红线（禁区）安全区（可落地）
车主会 / 社团 / 同乡会 《社团条例》非牟利身份，《税务条例》第 88 条免税资格，《旅游业条例》第 634 章无牌旅行代理 收现金佣金（损害非牟利 / 免税身份） 会员福利采购：园区以批发价供货，车主会作为会员福利发放，不代收客户款项
代园区组团、代收费（= 无牌旅行代理） 仅做「引流 + 权益发放」，客户直接向园区支付
保险经纪 / 代理 / 保险公司 《保险业条例》第 41 章，保监局 IA《持牌保险代理 / 经纪操守守则》，对非保险产品的利益诱导限制 按保单数 / 引流人数向保险方计酬（非保险对价） 单向会员折扣：园区向保单持有人提供会员价，不与投保行为一一挂钩
「投保即送门票」（构成违规 in-centive） 联合品牌活动费：按项目付费办活动，需律师意见确认灰区
代办机构（港车荟类） 一般商业公司，无特殊牌照，但涉跨境服务 代收客户门票款（= 二清 / 资金池） 服务费：发券，客户到园自付，园区按核销券数付固定服务费
预收客户款后跑路 T+1 核销结算 + 月结，不沉淀客户资金
车行 / 商会 一般商业 / 社团 代收费组团（同旅行代理风险） 服务费 / 会籍互认，均不代收客户款
◆ 三条共同红线（所有锚点必须遵守）

① 不做二清：客户消费一律进园区持牌商户号，绝不经商号账户过手。 ② 不带团、不代收客户款项：任何「代收费 + 组团」都会触发《旅游业条例》无牌旅行代理。 ③ 不对价于保险行为：保险类锚点给的优惠是第三方商户折扣，不是保险优惠，绝不写「投保送」。 这三条是法律底线，破任何一条都可能让园区与商号一起被查。

五、锚点开户与结算：端到端 8 阶段

这是用户要的「实际流程」骨架。从准入到复盘，每一步都对接一码通行的既有模块，不另起炉灶。

阶段 0 · 准入尽调（KYC）

主体资质核验，拒红线主体于门外

车主会查社团注册号 + 章程是否允许商业合作；代办查公司 BR + 口碑；保险查 IA 牌照号（代理人登记）。任一属「禁区」主体直接婉拒或转安全区通道。

阶段 1 · 锚点开户

生成唯一 MA 码 + 商号后台 + 选定合规通道

登记商号名 / 编号 / 行业 / 合规通道类型 / 结算方式 / 联系人。系统自动生成 MA-行业-序号 与 merchant ledger 账本。同步下发「锚点物料包」（一码多媒介模板）。

阶段 2 · 物料投放（一码多媒介）

同一锚点，按媒介挂子参数

海报用 ?s=poster、WhatsApp 群用 ?s=ws、EDM 用 ?s=edm、门店立牌用 ?s=card。后台按子参数拆分各媒介转化，但不新开码。

阶段 3 · 客户扫码 → 归因 → 礼包

首扫即打标签，发「车主礼包」

客户扫 MA 码 → 弹隐私同意 → 生成 customer_id 并打 source_merchant=MA-xxx → 领车主礼包（停车券 + 鱼宴抵扣 + 水疗体验）→ 引导绑车牌生成 OnePass。归因窗口启动（180 天）。

阶段 4 · 到园 → 核销 → 归集

进 OnePass 链路，消费实时归集

客户走 qr-pass 的自驾三步链路。园内核销的每一笔二销（水疗 / 礼盒 / 餐饮）实时写入该 MA 的 merchant ledger。商号后台可见聚合数据，不可见个人明细或风控评分。

阶段 5 · 结算（按合规通道）

四类通道，分主体兑付

会员福利采购：商号先批发付款、园区发货（非佣金）；服务费：按月核销券数付固定费（T+1 冻结、月结）；单向折扣：无现金对价，仅系统折扣标识；活动费：按项目结案付。详见第八节经济测算。

阶段 6 · 复购窗口 → 分层计酬

首单全酬，窗口内半酬，窗口外转股息

180 天内复购按 50% 计；超 180 天不再现金计酬，转「会员股息」——该客户消费额 1.5% 计入锚点权益池（实物、不可变现）。防止首获客成本被终身摊薄。

阶段 7 · 季度复盘 → 锚点升降级

S / A / B 三级，动态调权

按季度送客量 + 核销率 + 复购率评级：S 级（>50 车/季）给首页位与优先活动名额；B 级（<10 车/季）预警并冻结新券，连续两季不达标清退。锚点对园区的价值以数据说话。

六、客户侧实际操作流程（6 步，含界面话术）

这是把锚点「接进具体流程」的落地形态。客户全程只感觉「扫了个车主会的码，领了包」，其余无缝并入一码通行。

以「香港某车主会会员扫 MA-CLUB001」为例

第 1 步 · 触发

群内看到「会员专享 · 珠海生态园车主礼包」

车主会 WhatsApp 群发带 ?s=ws 的 MA 码。话术：「本周二三免预约，会员专属停车券 + 鱼宴抵扣已就位。」

第 2 步 · 扫码（≈20 秒）

弹窗：隐私同意 + 领礼包 + 跳转绑牌

屏显文案：「你是 XX 车主会 会员 · 已解锁车主礼包（停车券 1 + 鱼宴 HK$80 抵扣 + 水疗 30 分钟体验）。继续绑定车牌即可使用。」—— 全程不出现「佣金」「返佣」字样。

第 3 步 · 绑车牌（自动并入 OnePass）

输入 / 拍行驶证 → 生成 OnePass → 选周中时段

系统识别这是 MA 来源客户，自动打标签。选周二或周三（免预约日），预约生效。

第 4 步 · 到园（0 步操作）

LPR 识别车牌 → 放行 → 预授权

车道屏：「欢迎 XX 车主会会员 · 礼包已激活 · 预授权 HK$500」。

第 5 步 · 园内一码核销

OnePass 核销全园，二销实时计入该锚点

鱼宴、水疗、礼盒、充电桩——每笔消费写入 MA-CLUB001 账本，但客户无感。

第 6 步 · 离园 + 复购钩子

自动结算 + 推「邀请同会车友」裂变码

结算明细注明「本单含 XX 车主会会员礼包抵扣」。推送 30 天复购券 + 专属裂变码（裂变码归属原锚点，不另开码）。

年度转化漏斗（按首批 40 活跃锚点估算）。曝光 120 万（群 + 门店 + EDM）→ 扫码 5 万（4.2%）→ 绑牌 2.4 万（48%）→ 到园 1.5 万（62.5%）→ 产生二销 1.1 万 → 180 天复购 3,600。到园 1.5 万人/年 ≈ 1,250 人/月，与锚点渠道 1,000–1,250 的月度目标一致。

七、归因与分层计酬机制

永久归因若不设窗口，首获客成本会被无限摊薄。窗口 + 分层让「锚点的钱花在该花的地方」：拉新重奖，存量轻奖，老客沉淀转非现金。

◆ 一句话总结这一页

商号唯一锚点把「渠道」从抽佣中介重定义为获客合伙人： 每个商号一张永久码、一个账本、一条按主体性质定制的合规结算通道。 它接在 OnePass 前面喂流量，落在「周二三免预约日」上填周中谷， 并用 180 天分层计酬把首获客成本锁在拉新而非养客。 这套机制本身就是 v2 渠道反转的可复制资产——它可以从生态园卖到任何目的地景区。
