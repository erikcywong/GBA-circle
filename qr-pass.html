一、范式转变：归因码 → 通行码

这不是加一个功能，是换一个主命题。两者的设计约束、失败后果、对数据的要求完全不同。

◆ 原 L2 方案没有被浪费，只是主从关系反了

原作者设计的 channels / qrcodes / orders / commissions / settlements 五张表， 在 20% 团客场景下依然逐字可用——它们处理的就是「旅行社带来的团，佣金怎么算、怎么结」。 新增的是 passes / vehicles / gates / lpr_events / redemptions / wallet_txns 六张表， 处理「自驾散客怎么进门、怎么核销、怎么复购」。 不是推翻重做，是在原系统旁边接一根主干。

二、码体系重构：从 9 类平铺到三层结构

原方案的 9 类码是平铺的，彼此没有层级关系，导致归因裁决规则无处安放。 新结构按「身份层 / 场景层 / 渠道层」三层组织，每层职责唯一。

I身份层（长期）· 3 类

车牌码 — 一次绑定，终身无感。核心身份载体，用于入园放行与停车计费。

OnePass 动态码 — 小程序内每秒刷新的二维码。用于所有园内核销，防截图盗用。

会员 ID — 不可见，用于跨次归集消费、积分、权益、复购触达。这是一码通行真正的资产。

II场景层（现场）· 4 类

核销点码 — 鱼餐馆、水疗、采摘、礼盒店、咖啡棚、茶庄、鱼塘、民宿，每点一码。

闸机码 — 车牌识别失败时的兜底二维码，贴在车道旁。

拼车码 — 无车自由行的口岸拼车班次码（原「巴士码」改造）。

时段码 — 分时段预约的入场时段标识。

III渠道层（归因，仅 20%）· 4 类

旅行社渠道码 — 保留原设计，仅服务团客归因。

团码 — 团客入团、点人数，保留原设计。

推荐码 / 社团码 — 老客裂变与社团团长使用，按实物回馈而非现金佣金。

虚拟渠道码 — 小红书 / Facebook / 抖音，直接归园区直营。

◆ 入口层（L0）：商号唯一锚点，从前面喂流量

这三层（身份 / 场景 / 渠道）之上，还有一层入口层 L0 = 商号锚点： 车主会、港车北上代办机构、保险公司各持一张永久唯一码（MA-行业-序号）， 客户首次扫该码即被打上来源标签、领取车主礼包并引导绑车牌，之后平滑切入下面的 OnePass 链路。 L0 不是 OnePass 的替代品，而是它的获客前端——详见 商号锚点计划。锚点渠道与周中免预约日结合，是填谷的主工具。

◆ 关键设计：团客可以「升级」为通行码

团客入园后，现场扫一次 OnePass 生成码，即可把园内所有二次消费从团账里剥离，直接算作园区直营。 这意味着旅行社只拿到门票那一部分的 15% 佣金，水疗、酒水、礼盒、认养全部不用付佣金。 这是原方案（按整团归因）里没有的设计，也是渠道反转最锋利的一刀—— 它把「二销」这块利润从渠道分成里彻底解放出来，同时旅行社的账面佣金率不变（仍 15%）， 感知上没有受损，抵触最小。

三、三条通行链路

对应渠道结构里的三类客群。注意每条链路的最后一步都是「自动结算 + 推送明细」—— 这一步同时完成三件事：收款、生成数据资产、触发复购触达。

链路 A · 自驾家庭（占 55%）—— 全流程只有 3 步操作

行前 · 第 1 步

小程序选日期时段 + 绑车牌

选时段（分时削峰）→ 输入车牌或拍行驶证自动识别 → 微信/支付宝授权免密支付 → 收到 OnePass 与预约凭证。支持「不绑车牌」降级为纯动态码，但绑牌可免停车费。

到园 · 0 步操作

闸机 LPR 识别车牌 → 自动放行

车道屏显示「欢迎 · 3 人已入园 · 预授权额度 HK$500 · 车位于 B 区 27 号」。同时后台完成预授权。识别失败自动降级为扫车道兜底码，永远保留 1 条人工车道。

园内 · 第 2 步

出示 OnePass 一码核销全园

鱼餐馆点单、水疗预约、采摘、礼盒、咖啡棚、茶庄——全部同一个码，POS 扫码即核销、即扣款（走预授权额度，无需每笔输密码）。

离园 · 0 步操作 + 第 3 步确认

闸机识别车牌 → 自动结算

按实际消费结算，多退少补；推送电子小票与消费明细。第 3 步是「看一眼明细」，不是必须操作。

事后 · 自动化

积分入账 + 复购券 + 邀请裂变码

自动加入对应私域群（自驾家庭群），推送 30 天内有效的复购券与邀请码。

链路 B · 无车自由行（占 25%）

步骤动作载体核销
1购买「口岸拼车 + 入园套票」小程序生成 OnePass
2选口岸（港珠澳大桥 / 横琴 / 拱北）+ 班次小程序锁定拼车座位
3上车扫码拼车码核销座位
4到园门口扫 OnePass 入场步行闸机码核销门票

这是原 L1「口岸接送」能力的正确残留形态：不做包团，做班次。 按小时发车的 7 座车，4–6 人成行即发，成本由乘客分摊（约 HK$60–90/人），园区不承担空驶风险。

四、园内 11 个核销点

每个核销点都是一个数据采集口。这不是收银设备清单，而是用户画像的 11 个传感器。

1入口闸机 ×2

LPR 车牌识别、预授权、人数确认、停留时长开始计时。

2鱼餐馆

点单 + 核销 + 加菜。记录口味偏好（辣/清淡）、桌型（家庭/情侣）。

3水疗中心

项目、时长、加钟。利润引擎，也是 attach 率的关键观测点。

4蔬果采摘

按斤计价，亲子客群主力。记录同行儿童数量（家庭画像）。

5鱼塘体验

垂钓 / 捞鱼 / 喂鱼 / 认养。认养是一次性大额预付，需单独流程。

6雾化咖啡棚

参观、品鉴、烘豆体验、豆子零售。差异化内容载体。

7茶庄

品茶、采茶、茶浴体验券核销。银发客群停留点。

8礼盒 / 特产店

活鱼礼盒、咖啡豆、茶。二销与离园前消费的最后机会。

9民宿前台

入住登记、房型升级、加早餐。两日一夜客群。

10充电桩

充电时长与电量。识别 EV 车主，是港澳客群的高价值标签。

11出口闸机

结算、抵扣停车费、发放复购券、触发私域入群。

五、支付与结算架构

原方案最正确的一句「客户消费先进入园区统一商户号 / 持牌支付机构，不得先进旅行社账户」必须原样保留。 新增的难点是：港澳客户的钱怎么进来，以及离园自动扣款怎么做到合规。

资金入口：必须支持港澳钱包

  • AlipayHK — 香港用户渗透率高，小程序内可直接调起
  • WeChat Pay HK — 微信生态内最顺滑，与小程序同源
  • PayMe — 香港本地高频，但需独立集成
  • 八达通（Apple Pay / 实体） — 银发客群必备兜底
  • Visa / Mastercard 3DS — 境外卡通道，覆盖所有剩余情况
  • 微信支付 / 支付宝（内地版） — 内地客与本地客

港币与人民币双币标价。汇率在预约页明示并锁定 24 小时，避免现场争议。

免密支付：合规的三条硬约束

  • 必须走持牌机构 — 免密代扣属支付业务，园区不得自建资金池，也不得自建代扣协议
  • 必须先预授权 — 入园时冻结额度（建议 HK$500/车），离园按实际消费 capture，多退少补
  • 必须可随时撤销 — 小程序内一键解除免密协议，且协议文本单独签署、单独同意

拒付率是这条链路的生命线：任一通道拒付率 >2% 立即停用。同时保留「现场逐笔付款」的降级路径。

◆ 第 1 项是生死线

港澳车牌格式与内地差异大，且港车北上车辆多挂临时电子牌，标准 LPR 字库很可能识别不了。 这一项花 2 周、几千块钱就能测出来。在测试通过之前，不要采购任何闸机硬件，不要给客人任何「车牌即入」的承诺。 不通过也有 Plan B：全部改扫动态码 + 人工车道，只是客户体验从 3 步回到 4 步，不影响模式成立。

POST /gate/lpr闸机上报识别结果须在 300ms 内返回放行指令；超时默认放行 + 事后补录
POST /pass/redeem核销点 POS 核销支持离线核销 + 恢复后补传，防重复核销
POST /wallet/preauth入园预授权必须走持牌通道；记录授权凭证号
POST /wallet/capture离园结算多退少补；失败自动转人工收银
GET /pass/{id}/statement行程与消费明细客户可见自身数据（PIPL 查阅权）
POST /pass/invite生成裂变邀请码防刷：同设备 / 同 IP 限频
GET /admin/gates/health闸机与 LPR 健康度识别失败率 >5% 自动告警

八、车牌合规：一码通行最容易被忽略的风险

车牌在 PIPL 下属于可识别特定自然人的敏感个人信息；港澳的 PDPO 与澳门《个人资料保护法》 对「轨迹 + 消费」组合的敏感度更高。以下是必须写死进产品设计的规则。

#规则具体要求
1单独同意车牌采集与免密支付必须是两个独立的同意开关，不与「同意隐私政策」捆绑勾选
2三处告知入口立牌 + 车道屏 + 小程序弹窗，同步说明采集目的、范围、保留期限、撤回方式
3目的限定车牌仅用于通行放行与停车计费；禁止用于营销画像、禁止与消费数据做关联分析
4保留期限原始抓拍影像 7 天自动删除；车牌与通行记录 90 天；超期匿名化
5禁止跨境回传港澳客数据在境内处理，不回传香港/澳门服务器；营销触达使用匿名化标签
6必须有不绑牌的路径提供「不绑车牌」的降级选项（改扫动态码，不享免费停车），不得强制
7查阅与删除权小程序内提供「我的数据」页面，可查阅、导出、申请删除
8三地法规分别适配内地 PIPL + 香港 PDPO + 澳门第 8/2005 号法律，隐私政策需出三套文本
◆ 24 小时冷静期（建议保留原方案的这条设计）

免密支付授权后 24 小时内可无条件解除；认养等大额预付设 7 天冷静期。 这些不是负担——它们是港澳客户愿意绑定车牌的前提条件。 港澳客对「被记录行程」的敏感度远高于内地客，主动给出可撤回的承诺，比事后解释划算得多。

九、分期实施

P1第 1–2 月 · 通行 MVP

预约 + 绑车牌 + 动态码入场 + 园内扫码核销 + 停车计费 + T+1 结算。

此阶段不做免密支付、不做无感进场，先把「一码核销全园」跑通。验收标准：连续 7 天无核销失败事故。

P2第 3–4 月 · 无感与增长

LPR 无感进场 + 预授权 + 离园自动结算 + 会员积分 + 邀请裂变 + 认养模块。

验收标准：车牌识别率 ≥97%、免密开通率 ≥60%、会员注册率 ≥70%。任一不达标先修不做下一步。

P3第 5–8 月 · 渠道与风控回归

团客归因模块（复用原 L2）+ 授信风控 + 数据看板 + 跨渠道对账。

注意顺序：系统先服务 80% 的自驾直客，最后才服务 20% 的渠道。原方案的顺序是反的。

◆ 一句话总结这一页

原方案做了一套「分钱系统」，新方案要做一套「认人系统」。 分钱系统只在渠道占比 100% 时是核心；认人系统在任何渠道结构下都是核心， 因为它决定园区是否拥有自己的客户。 把系统建在「认人」上，是这次渠道反转唯一不可妥协的技术决策。
