Section 02 / Logic Audit

逻辑性分析

逐条对账三份文档：哪些设计是自洽的、哪些数字互相打架、哪些规则整段缺失。 结论先说：逻辑骨架成立，但有 7 处硬冲突 会在签约第一个月内集中爆发， 另 5 条关键规则整段缺失——不是写错了，是没写。

逻辑栈自洽 7 处硬冲突 5 处规则缺失 缺 L3 → L1 反馈回路

一、逻辑栈：三层是通的，但只往下流

三份文档构成一条完整的数据流：业务层定规则 → 系统层执行规则 → 风控层修正规则。方向没问题。问题是这条链是单向的。

L1
业务层 · 定义
输出：产品清单、价格带、渠道清单、佣金承诺、激励政策
规则来源
L2
系统层 · 执行 ↑ 承接 L1 的规则，转成可计算的引擎
输出：归因结果、佣金计算、结算单、团码核销、巴士跟踪、客户画像
规则执行
L3
风控层 · 修正 ↑ 消费 L2 的数据，产出授信与锁位决策
输出：授信额度、资源锁位/释放、违约记录、虚报预警
规则修正
◆ 结构性缺口：缺一条 L3 → L1 的反馈线

L3 采集了全案最宝贵的资产——渠道履约质量数据（准时付款率、退款率、虚报率、上座率）。 但这条数据流没有回到 L1 去重新定级渠道政策。 结果就是：一个履约 100% 的好渠道，和一个三次虚报的坏渠道，享受同一阶梯佣金、同一返点比例——唯一区别只是"能不能锁位"。

而 L1 的渠道分级完全是销量驱动的（满 1000 人返 2%、满 3000 人返 5%）。 销量 ≠ 质量。一个靠虚报人数冲量的渠道，反而比一个老实做量的小渠道拿到更多返点。 这是激励机制设计上的方向性错误。

修正建议

把 L1 的渠道分级从「单轴销量」改为「销量 × 履约质量」双轴：履约分 ≥ 80 的渠道才解锁最高返点档；连续两月履约分 < 50 的渠道自动降档并转为全额预付。这样 L3 的数据就变成了 L1 的政策输入，闭环成立。

三、7 处硬冲突逐条对账

"硬冲突"的定义：同一件事，两份文档给出不同答案，且签约后在实务中必须二选一。这类冲突不会自己消失，会在第一次对账时爆发。

佣金率对比：L1 取原文价格区间与佣金区间折算的中值，L2 取文档明确列出的百分比。

C1 佣金按"单团人数"还是按"月度累计"？

10 人以下 15%，10—30 人 20%，30 人以上 25%— L1 阶梯佣金
香港旅行社 / 一日游 / 20% / 月满 50 人— L2 佣金规则表

为何必炸：一个 35 人的团，按 L1 拿 25%，按 L2 只有 20%。渠道必然主张 L1。更糟的是 L1 的口径会被系统性套利——代理商可以把一个 35 人团拆成 3 个小团，或者把 3 个小团拼成 1 个大团，只挑对自己有利的算法。

建议统一为：基础佣金按月度累计人数分档（避免拆分套利），单团规模只作为一次性奖励（如满 30 人团额外送水疗体验券），不参与百分比计算。

C2 自由行套票佣金：13–27% 还是 10%？

自由行套票 建议价 299—399 港币/人 … 旅行社佣金 50—80 港币/人— L1
OTA / 自由行套票 / 10% / 核销后— L2 佣金规则表

折算：HK$50–80 对应 HK$299–399 的售价，佣金率是 12.5%–26.8%；L2 写死 10%。差了 2.7 倍。

建议：区分渠道类型。港澳门店旅行社 18%，OTA（Klook/KKday/Trip.com）10–12%，直客虚拟码 0%。按渠道类型定价，而不是一个套票一个价。

C3 两天一夜佣金：12–19% 还是 25%？

两天一夜 建议价 899—1299 港币 … 旅行社佣金 150—250 港币— L1
澳门旅行社 / 两日一夜 / 25% / 含民宿— L2 佣金规则表

折算：L1 口径下佣金率 11.5%–27.8%（中值约 18%），L2 给澳门渠道明确 25%。含住宿的团本身就重成本，25% 佣金 + 民宿成本 + 四餐 + 水疗，单位经济需要重新验算（见 盈利模式）。

C4 水疗佣金：HK$30–50 还是 10%？

水疗单卖，旅行社佣金 30—50 港币— L1 水疗专项
黄芳合作码 / 水疗+鱼宴 / 10% ；员工 / 水疗 / 10%— L2 佣金规则表

折算：鱼宴+鱼疗定价 HK$198–268，HK$30–50 固定佣金 = 11%–25%。与 L2 的 10% 不一致，且固定额佣金在涨价时不会自动调整（比例佣金会）。

建议：全案统一采用比例佣金，不出现固定额佣金。固定额只用于一次性激励（券、房券、现金奖）。

C5 渠道归属时效：终身归因 vs 非独家代理

客户扫码后终身或 90 天内消费都归因到该码— L2 黄芳合作码设计
非独家代理，先签 30—50 家— L1 给旅行社的政策

为何必炸：30–50 家非独家代理 + 长时效归因，是必然的抢单结构。同一个客人可能先是 A 社的团、三个月后自己带家人再来，扫了园区口的小红书码——这单算谁的？原文只给"黄芳码"写了规则，普通渠道码一个字都没写。

建议（必须写进合同）：末次点击归因 + 90 天有效 + 超过 90 天自动释放至园区直客池 + 同一团内以团码为唯一归因（团内不认个人码）。

C6 激励方向：激进获客 vs 保守风控

首团奖励 500—1000 港币车费补贴；季度销售竞赛送客前 3 名奖现金；满 1000 人返 2%，满 3000 人返 5%— L1
71–100 分：高风险，全额预付、暂停新团、资源不锁— L3 风控评分

为何必炸：同一个渠道，L1 在拼命鼓励它多拉客，L3 在拼命限制它的额度。新签约渠道天然是"无历史履约数据"的，按 L3 的模型（渠道类型与年限占 10% 权重）会被判为偏高风险，于是拿不到授信、要先全额预付。而 L1 承诺的第一印象是"你是我们的合作伙伴"。两套话术在同一个销售周期内打架。

建议：做一条明确的解锁曲线——新渠道前 2 个月全额预付（话术："系统统一规则"）→ 履约良好后自动解锁 50% 授信 → 稳定 6 个月后解锁全额月结。把风控从"门槛"改写成"进度条"。

C7 「静默」与「披露」的表述冲突

建议把它定义为"后台静默风控与应收信用模块"，而不是对渠道商完全隐藏的"秘密程序"— L3 开头
所有规则写入合同附件，渠道可查统一规则，但看不到自己的评分……不返回 risk_score、黑名单、逾期等级— L3 技术实现

判定：实质自洽，表述冲突。文档自己其实已经把这条路走对了——规则披露 + 评分脱敏，法理上完全站得住。但"静默""隐藏程序"这两个词会主动制造敌意。一旦被渠道或媒体写成「园区有一套秘密程序在悄悄克扣佣金」，前面所有合规努力归零，而且解释成本极高。

建议改名为：「履约信用与资源预锁机制」。同一套东西，一个名字是暗箱，一个名字是规则。

四、两处边界冲突（不致命但需预先对齐）

B1 90 天首发团 vs MVP 2–3 个月

时间上基本吻合（90 天 ≈ 3 个月），但风险在于"首发团"通常是营销驱动的硬日期，而系统上线是工程驱动的软日期。如果首发团早于归因系统上线，第一波客源将全部无法归因——渠道拿不到佣金，信任一次就没了。

建议：首发团若必须早于系统上线，就用"简易归因"兜底（专属优惠码 + 人工登记渠道号），确保佣金可追溯，系统上线后补录。

B2 四套价格并存的护栏缺失

散客套票 HK$299–399、旅行社卖 HK$399–599、OTA 价、会员价——四套价格同时在市场上流通。原文没有任何价格护栏条款。游客在园区现场用手机搜到 OTA 更便宜，是投诉与差评的经典来源。

建议：设置最低零售价（MAP）条款——渠道不得低于门市价 9 折销售，违规即扣减佣金；会员价只对已消费客户开放，且不与渠道价在同一可见页面出现。

五、5 条整段缺失的关键规则

这五项不是"写得不好"，是"完全没写"。每一项都会在运行 3 个月内变成实际纠纷。

  1. 渠道归属裁决规则。首触还是末触？团码与个人码谁优先？员工推荐码与渠道码冲突时算谁的？直客池保护期多长？——30–50 家非独家代理下，这是最高频的争议源，必须先于签约定死。
  2. 财务与成本模型。三份文档合计出现 0 个成本数字。没有成本，就无法判断"30 人以上 25% 佣金"这条规则是否可承受——也就是说，无法判断这条政策本身是否合法地可持续。这是全案最大的逻辑空洞。
  3. 资源容量与承载上限。T-3 锁位规则成立的前提是知道总容量：车位多少个、餐位多少个、水疗位多少个、民宿房多少间。原文全程未出现任何容量数字。没有容量，"锁位 / 释放"就是一句空话，也无法防止超卖。
  4. 渠道违约处置与退出机制。原文只有"后台记录渠道违约"四个字。缺少：违约金比例、保证金没收条件、已预售客户的安置责任划分、黑名单申诉与解除机制、渠道主动退出的佣金清算规则。
  5. 价格护栏与渠道平权条款。散客价/OTA 价/旅行社价/会员价四轨并存，缺最低零售价（MAP）条款与违规罚则。同时缺"统一规则"的书面承诺——L3 提到的"不能对渠道商进行秘密歧视性定价"需要一条对应的规则公示与变更通知机制（规则变更提前 30 天书面通知）。
◆ 一句话总结本节

这套方案的逻辑问题不在"想得不深"，而在"写得太像招商文案"——每个数字都漂亮，但没有一个数字被另一份文档校验过。 7 处冲突里有 4 处是佣金口径，而佣金恰恰是全案唯一直接决定钱怎么分的规则。 把佣金口径统一、把归属规则写死、把成本模型补上，这三件事做完，逻辑性可以从 6 分提到 8.5 分。
